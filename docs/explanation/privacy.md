# 隐私与数据去向

AllDayRec 的出发点是：全天的录音是很私人的数据，应该放在你自己的机器上。但它并不是完全离线的：音频和文字会发给你选的服务。这一页讲清楚什么留在本地、什么发给了谁。

## 留在你服务器上的

- 原始录音：每台设备每小时一个文件，一直保留（见[数据目录](../reference/data.md)）。
- 数据库 `live.db`：转写、对话、摘要、待办、说话人、声纹。
- 语音检测和声纹：FireRedVAD 和 ReDimNet2 在本机 CPU 上跑，声音特征不出服务器。
- 逐段声纹（`tenants.json` 的 `seg_emb`，默认关）：打开后，定稿时每个识别分段算出的声纹都存进 `live.db` 的 `seg_emb` 表。这是佩戴者附近所有说话人的声纹，包括没有同意过的路人，只用于以后在本机重新聚类和复核说话人。关着时一条也不存；句子被重新定稿、音频被修剪时，对应的声纹在同一个事务里一起删掉；删掉这个人的 `live.db` 就全部删掉。

不需要注册任何账号；网页和 API 使用 `tenants.json` 里的 token，MCP 还接受单独创建、可作废的 [AI 连接网址](../how-to/connect-mcp.md#创建-ai-连接网址)。

## 发出去的

| 什么 | 发给谁 | 什么时候 |
|---|---|---|
| 音频片段 | 你在 `ENGINE`（和 `DRAFT_ENGINE`、`ENGINE_FALLBACK`）里选的语音识别服务 | 每次转写。设成 `local` 的那一层不发 |
| 说出的问题（「问 AI」按住说话） | 阿里云百炼的流式语音识别，只在 `ENGINE`、`DRAFT_ENGINE`、`ENGINE_FALLBACK` 里已有 `qwen` 或 `qwen-stream` 时；否则是上面那一行的服务 | 边说边发；流式识别失败时整段再交给上面那一行的服务 |
| 转写文字 | `LLM_BASE_URL` 指向的大模型服务 | 写摘要、名字提示、人物卡片、每日回顾、实时分析，以及回答「问 AI」时。说话不到 60 秒的对话不写摘要（进行中时点过「立即总结」的除外） |
| 你的 AI 助手查到的转写和摘要 | 你自己的 AI 助手用的厂商 | 你用 [MCP](../how-to/connect-mcp.md) 接入之后，助手每次调用工具时 |
| 监控指标（`lr_*`，不含内容） | `VM_INGEST_URL` | 只有设了这个变量时，每分钟一次 |

这些服务各有自己的条款。想做到音频和文字都不出自己的机器：用 `ENGINE=local`，再把 `LLM_BASE_URL` 指向你自己运行的 OpenAI 兼容服务（vLLM、llama.cpp、Ollama），模型要支持工具调用和 JSON 输出。

每次语音识别和大模型调用都记在 `calls` 表里，只记耗时、结果和用量，不记内容；MCP 请求的日志只记方法、工具和返回的字符数，不记参数和内容。

AI 连接网址的秘密只在创建时返回，数据库保留哈希和短前缀。服务器关闭访问日志，性能记录使用 `/mcp` 路由；反向代理的访问日志会包含完整网址，应关闭该路径日志或脱敏。使用 Cloudflare Tunnel 时，公网 TLS 在 Cloudflare 终止，流量经过它的网络。

## 人物档案

人物页上的「AI 档案」是大模型根据你和某个人的对话写的一份档案：TA 是谁、TA 自己说过的事、最近在忙什么、别人怎么说 TA、还没了结的事。每一条都带出处，点开就是那段对话里的那一句。

- **存了什么**：`live.db` 的 `profiles` 表，每个人一行：档案的每一条、它引用的对话和时间、生成用的模型和用量。打开 `persona_v2` 后还存每段被引用对话的一个哈希（不是内容），用来判断档案是否还成立。
- **发出去了什么**：生成时把证据发给 `LLM_BASE_URL` 的大模型。默认是各段对话的摘要和这个人的要点；租户打开 `persona_v2`（见[配置](../reference/configuration.md#tenants-json)）后，改成**这个人自己说的原句**（每段最多 8 句、最近 40 段对话），加上你对 TA 说的待办原句，和别人提到 TA 名字的前后几句原文。
- **什么时候生成**：在人物页点「生成」时；之后有这个人的对话写完摘要，就自动重新生成一次。
- **只写谁**：打开 `persona_v2` 后，只给你命名过的人写，匿名的 S 标签不写。被认成 TA、但只有几秒碎片的那一段，人很多的场景里 TA 的标签吸走了大部分说话的那一段，以及对 AI 说的话、外放的视频和音乐、口述，都不当证据。
- **不写什么**：提示词禁止推断或写下健康、性取向、宗教、政治立场、民族、犯罪记录、财务细节；别人的转述不会写成 TA 本人的观点；证据不到 5 天时不写性格和习惯。
- **给谁看**：只有这个租户自己（网页和 API 的 token）。改了名字、合并或拆分了说话人以后，旧档案作废，不再显示，下次按新的标签重新生成。
- **怎么删**：删一个人的档案：`sqlite3 live.db "DELETE FROM profiles WHERE name = '<名字>'"`；全部删掉：`DELETE FROM profiles`。删掉以后，除非再点「生成」，不会自动再写。

## 环境声音

默认关。打开后（[配置](../reference/configuration.md#可选-环境声音)：`SOUND_MODEL`，加上租户的 `"sound": true`），服务器给全部录音算环境声音的打分：每 10 秒（或每 0.48 秒）一帧，哪些声音（汽车、音乐、炒菜、电视、流水……）有多像，以及当时的音量，存在 `live.db` 的 `sounds` 表里。它算的是全部录音，包括没人说话的时段，所以能看出你在什么地方、在做什么，比转写覆盖得更全。

- 在本机 CPU 上算；设了 `INFER_URL` 时在你自己的推理服务上算，音频只发给那里。打分不发给任何第三方，也不进监控指标（指标只有秒数和次数）。
- 修剪（`trim.py`）丢掉没人说话的录音时，这些打分留着：音频没了，那段时间有什么声音的记录还在。`mn10_as` 的每帧结果和两个模型的每分钟汇总一直保留，`yamnet` 的每帧结果保留 30 天。
- 不想要了：停掉 `SOUND_MODEL` 或去掉租户的 `"sound"`，再删表里的行，例如 `sqlite3 live.db "DELETE FROM sounds"`（只删某台设备加 `WHERE device = '<设备名>'`）。删了的部分要再算，得用回填命令从录音重算，录音已修剪掉的就算不回来了。只去掉租户的 `"sound"`、`SOUND_MODEL` 还开着时，这个租户的修剪照样要等打分，要修剪就加 `--allow-unscened`。

## 为什么保留原始录音

有的同类产品转写完就删掉音频。AllDayRec 反过来：每句话都能点开回放核对，转写错了有底稿可对；以后有了更好的模型，还能把过去重新转写一遍。代价是磁盘空间，以及这些录音需要你自己保管好。

## 录到别人

全天录音一定会录到别人。请告知对方，需要时取得同意，遵守当地法律；有些地方要求所有参与方都同意。

用 MCP 把数据交给 AI 助手时，转写里别人说的话也会发给助手的厂商。录音里的话也可能被当成指令：在用这个连接的会话里，不要给联网和 Shell 工具开自动批准。
