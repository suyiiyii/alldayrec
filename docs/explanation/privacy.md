# 隐私与数据去向

alldayrec 的出发点是：全天的录音是很私人的数据，应该放在你自己的机器上。但它并不是完全离线的：音频和文字会发给你选的服务。这一页讲清楚什么留在本地、什么发给了谁。

## 留在你服务器上的

- 原始录音：每台设备每小时一个文件，一直保留（见[数据目录](../reference/data.md)）。
- 数据库 `live.db`：转写、对话、摘要、待办、说话人、声纹。
- 语音检测和声纹：FireRedVAD 和 ReDimNet2 在本机 CPU 上跑，声音特征不出服务器。

不需要注册任何账号；服务器只认 `tenants.json` 里的 token。

## 发出去的

| 什么 | 发给谁 | 什么时候 |
|---|---|---|
| 音频片段 | 你在 `ENGINE`（和 `DRAFT_ENGINE`、`ENGINE_FALLBACK`）里选的语音识别服务 | 每次转写。设成 `local` 的那一层不发 |
| 转写文字 | `LLM_BASE_URL` 指向的大模型服务 | 写摘要、名字提示、人物卡片、每日回顾、实时分析，以及回答「问 AI」时。说话不到 60 秒的对话不写摘要 |
| 你的 AI 助手查到的转写和摘要 | 你自己的 AI 助手用的厂商 | 你用 [MCP](../how-to/connect-mcp.md) 接入之后，助手每次调用工具时 |
| 监控指标（`lr_*`，不含内容） | `VM_INGEST_URL` | 只有设了这个变量时，每分钟一次 |

这些服务各有自己的条款。想做到音频和文字都不出自己的机器：用 `ENGINE=local`，再把 `LLM_BASE_URL` 指向你自己运行的 OpenAI 兼容服务（vLLM、llama.cpp、Ollama），模型要支持工具调用和 JSON 输出。

每次语音识别和大模型调用都记在 `calls` 表里，只记耗时、结果和用量，不记内容；MCP 请求的日志只记方法、工具和返回的字符数，不记参数和内容。

## 为什么保留原始录音

有的同类产品转写完就删掉音频。alldayrec 反过来：每句话都能点开回放核对，转写错了有底稿可对；以后有了更好的模型，还能把过去重新转写一遍。代价是磁盘空间，以及这些录音需要你自己保管好。

## 录到别人

全天录音一定会录到别人。请告知对方，需要时取得同意，遵守当地法律；有些地方要求所有参与方都同意。

用 MCP 把数据交给 AI 助手时，转写里别人说的话也会发给助手的厂商。录音里的话也可能被当成指令：在用这个连接的会话里，不要给联网和 Shell 工具开自动批准。
