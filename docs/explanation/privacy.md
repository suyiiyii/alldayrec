# 隐私与数据去向

AllDayRec 的出发点是：全天的录音是很私人的数据，应该放在你自己的机器上。但它并不是完全离线的：音频和文字会发给你选的服务。这一页讲清楚什么留在本地、什么发给了谁。

## 留在你服务器上的

- 原始录音：每台设备每小时一个文件，一直保留（见[数据目录](../reference/data.md)）。
- 数据库 `live.db`：转写、对话、摘要、待办、说话人、声纹。
- 语音检测和声纹：FireRedVAD 和 ReDimNet2 在本机 CPU 上跑，声音特征不出服务器。
- 逐段声纹（`tenants.json` 的 `seg_emb`，默认关）：打开后，定稿时每个识别分段算出的声纹都存进 `live.db` 的 `seg_emb` 表。这是佩戴者附近所有说话人的声纹，包括没有同意过的路人，只用于以后在本机重新聚类和复核说话人。关着时一条也不存；句子被重新定稿、音频被修剪时，对应的声纹在同一个事务里一起删掉；删掉这个人的 `live.db` 就全部删掉。

不需要注册任何账号；网页和 API 使用 `tenants.json` 里的 token，MCP 还接受单独创建、可作废的 [AI 连接网址](../how-to/connect-mcp.md#创建-ai-连接网址)。

## 发出去的

| 什么 | 发给谁 | 什么时候 |
|---|---|---|
| 音频片段 | 你在 `ENGINE`（和 `DRAFT_ENGINE`、`ENGINE_FALLBACK`）里选的语音识别服务 | 每次转写。设成 `local` 的那一层不发 |
| 说出的问题（「问 AI」按住说话） | 阿里云百炼的流式语音识别，只在 `ENGINE`、`DRAFT_ENGINE`、`ENGINE_FALLBACK` 里已有 `qwen` 或 `qwen-stream` 时；否则是上面那一行的服务 | 边说边发；流式识别失败时整段再交给上面那一行的服务 |
| 转写文字 | `LLM_BASE_URL` 指向的大模型服务 | 写摘要、名字提示、人物卡片、每日回顾、实时分析、推断地点（租户开了 `place`），以及回答「问 AI」时。说话不到 60 秒的对话不写摘要（进行中时点过「立即总结」的除外） |
| 你的 AI 助手查到的转写和摘要 | 你自己的 AI 助手用的厂商 | 你用 [MCP](../how-to/connect-mcp.md) 接入之后，助手每次调用工具时 |
| 监控指标（`lr_*`，不含内容） | `VM_INGEST_URL` | 只有设了这个变量时，每分钟一次 |

这些服务各有自己的条款。想做到音频和文字都不出自己的机器：用 `ENGINE=local`，再把 `LLM_BASE_URL` 指向你自己运行的 OpenAI 兼容服务（vLLM、llama.cpp、Ollama），模型要支持工具调用和 JSON 输出。

每次语音识别和大模型调用都记在 `calls` 表里，只记耗时、结果和用量，不记内容；MCP 请求的日志只记方法、工具和返回的字符数，不记参数和内容。

AI 连接网址的秘密只在创建时返回，数据库保留哈希和短前缀。服务器关闭访问日志，性能记录使用 `/mcp` 路由；反向代理的访问日志会包含完整网址，应关闭该路径日志或脱敏。使用 Cloudflare Tunnel 时，公网 TLS 在 Cloudflare 终止，流量经过它的网络。

## 人物档案

人物页上的「AI 档案」是大模型根据你和某个人的对话写的一份档案：TA 是谁、TA 的事、最近在忙什么、别人怎么说 TA、还没了结的事。每一条都带出处。租户的 `persona_v2`（见[配置](../reference/configuration.md#tenants-json)）决定用哪种证据，两种分开写在下面。

**默认（`persona_v2` 关）**

- **发出去了什么**：生成时发给 `LLM_BASE_URL` 的大模型：最近 40 段有这个人的对话，每段的标题、摘要（前 300 字）和 TA 在那段的要点；TA 的待办和我答应 TA 的待办（最多 30 条，原文和截止时间）；别人说到 TA 名字或别名的句子（最多 30 处），每处带前后各两句原文和说话人标签。
- **存了什么**：`live.db` 的 `profiles` 表，每个人一行：档案的每一条、它引用的对话（待办和提及还有那一句的时间）、生成用的模型和用量。点开出处，对话类的是整段对话，待办和提及是那一句。
- **规则**：提示词要求每条写证据编号，代码丢掉没引用到给出证据的条目。除此以外没有别的限制：提示词让模型写家庭、习惯等事实，不区分 TA 自己说的和别人说的，没有敏感属性禁令，也不限天数。
- **改名以后**：旧档案照常显示，下次生成时才按新的标签。

**打开 `persona_v2` 后**

- **发出去了什么**：改成**这个人自己说的原句**：最近 40 段能当证据的对话（被跳过的不算数，所以可能往前追很远），每段最多 8 句；我对 TA 说的待办原句；别人说到 TA 的句子（最多 30 处）和前后各两句。不发摘要和要点。
- **只写谁**：只给你命名过的人写，匿名的 S 标签不写。摘要没写完、或没经过模型的对话整段不用；对 AI 说的话、外放的视频和音乐、口述不当证据；TA 不到 1 秒的句子不算。一段对话里有下面三种情况之一，TA 在这段的句子都不用：TA 的有效发言不到 15 秒（碎片）；有 10 个以上说话人、TA 的标签占了 70% 以上的说话（人多的场景吸走了别人的声音，外放、口述和对 AI 说的话里的标签不计数）；TA 有 5 句以上、其中 45% 以上不到 1 秒（短句并进来的）。「我」不受后两条限制。提及前后的句子只取那段对话里的，并过同样的门：不到 1 秒的不发，TA 在被跳过的那段对话里的句子也不发。
- **谁说的**：由代码按引用判断，不听模型的。一条只引用 TA 原句才算「TA 自己说的」；只要引用了别人的话（提及，或我说的），就归到「别人提到」。「TA 是谁」也一样，靠别人的话撑着的不写在这里，归到「别人提到」。
- **不写什么**：提示词禁止推断或写下健康、性取向、宗教、政治立场、民族、犯罪记录、财务细节，TA 自己说了也不写；这一条只靠提示词，代码不过滤。证据不到 5 天时不写性格和习惯：提示词要求，代码丢掉模型标成性格的条目，没标的拦不住。
- **存了什么**：除了上面那些，还存每段被引用对话的一个哈希（不是内容），用来判断档案是否还成立。点开出处就是那一句。
- **改名以后**：改了名字、合并或拆分了说话人或对话，用到的对话变了，旧档案作废，不再显示，下次按新的标签重新生成。关掉开关后，存着的档案照常显示。

**两种都一样**

- **什么时候生成**：在人物页点「生成」时；之后有这个人的对话写完摘要，就自动重新生成一次（「我」不自动）。打开 `persona_v2` 后，证据和上次一模一样时自动刷新不调模型。
- **给谁看**：只有这个租户自己（网页和 API 的 token）。
- **怎么删**：删一个人的档案：`sqlite3 live.db "DELETE FROM profiles WHERE name = '<名字>'"`；全部删掉：`DELETE FROM profiles`。删掉以后，除非再点「生成」，不会自动再写。

## 环境声音

默认关。打开后（[配置](../reference/configuration.md#可选-环境声音)：`SOUND_MODEL`，加上租户的 `"sound": true`），服务器给全部录音算环境声音的打分：每 10 秒（或每 0.48 秒）一帧，哪些声音（汽车、音乐、炒菜、电视、流水……）有多像，以及当时的音量，存在 `live.db` 的 `sounds` 表里。它算的是全部录音，包括没人说话的时段，所以能看出你在什么地方、在做什么，比转写覆盖得更全。

- 在本机 CPU 上算；设了 `INFER_URL` 时在你自己的推理服务上算，音频只发给那里。打分不发给任何第三方，也不进监控指标（指标只有秒数和次数）。
- 修剪（`trim.py`）丢掉没人说话的录音时，这些打分留着：音频没了，那段时间有什么声音的记录还在。`mn10_as` 的每帧结果和两个模型的每分钟汇总一直保留，`yamnet` 的每帧结果保留 30 天。
- 声音事件（对话上的声音标签、时间线上的声音条、按声音筛选、MCP 里的环境声音）是每次从这些打分现算的，不另外存；只有这个租户自己能看到：网页和 MCP 都要这个租户的 token 或它的 AI 连接网址，接到 MCP 的 Agent 会读到（再随它发给它用的模型服务商）。它只说听到了什么（说话、音乐、交通工具上、安静），不说在哪里，而且会错，所以界面上都写「可能」。
- 在标签或声音条上点「不对」，存进 `live.db` 的 `sound_wrong` 表：哪台设备的哪一段时间、哪个事件、当时用的模型、所在对话 id，不存声音和文字；只给这个租户自己看（`GET /api/sounds/wrong` 导出），以后用来改进门限。点「撤销」删掉那一行，全删用 `sqlite3 live.db "DELETE FROM sound_wrong"`。
- 不想要了：停掉 `SOUND_MODEL` 或去掉租户的 `"sound"`，再删表里的行，例如 `sqlite3 live.db "DELETE FROM sounds"`（只删某台设备加 `WHERE device = '<设备名>'`）。删了的部分要再算，得用回填命令从录音重算，录音已修剪掉的就算不回来了。只去掉租户的 `"sound"`、`SOUND_MODEL` 还开着时，这个租户的修剪照样要等打分，要修剪就加 `--allow-unscened`。

## 可能在哪里

默认关。租户开了 `"place": true`（见[配置](../reference/configuration.md#tenants-json)）后，每段对话写完摘要，服务器再调用一次大模型，推断你录这段时可能在什么地方（家、实验室或办公室、车上、地铁或高铁、餐厅、户外、商店、其他，外加原句里说出的具体地方：只取引用的那几句话里原样说出的词，说不出就只写类别），并写明依据：哪几句话、哪类环境声音、多少分钟。这是半敏感信息：单独一条只是猜测，攒多了就是你的行踪。

- **发出去的**：这段的转写（标出外放媒体和对 AI 说的话）、环境声音的分钟统计（租户也开了 `"sound"` 才有，见[环境声音](#环境声音)）和对话时间，发给 `LLM_BASE_URL` 的大模型服务，和写摘要时发的是同一份转写。说话不到 60 秒、没调用大模型写摘要的对话不推断。
- **存在哪里**：只存在这个租户 `live.db` 的 `summaries` 表里，作为摘要 JSON 的 `place` 字段，依据里带原句的时间和文字（转写里本来就有）。不进监控指标；`calls` 表只记这次调用的耗时和 token 数。
- **给谁看**：对话页摘要顶部；返回摘要的对话接口（`GET /api/conversations`、`GET /api/conversation/{id}` 等）也带着它，只给拿这个租户 token 的客户端。不进人物档案、每日回顾、「问 AI」和 MCP 工具的输出。模型没把握、依据对不上原文（引用的句子不在转写里，或者是外放、歌词、口述、对 AI 说的话）、或者没有一句原文依据（只有声音不算）时，只存一个空结果（`place` 的 `label` 为 null，免得同一份摘要再问一次），页面上什么都不显示。
- **敏感场所默认不推断**：医院、诊所、药店、妇产、心理咨询这类看病的地方，宗教场所、政治集会、警局和法院、戒断机构、性少数相关场所，默认一律不写。提示词禁止模型推断这类地方，代码再按一张关键词表兜底：具体地方或引用的句子里出现这类词时，同样只存空结果、不显示。这是保守的默认。
- **放开敏感场所**：租户同时开了 `"place_sensitive": true` 时，上面这类地方也照常推断和显示（比如「社区卫生服务中心」「教会」），换用不带禁令的提示词（地点里的 `prompt_version` 是 3，默认的是 2），也不再按关键词表过滤。其他规则一条不变：仍要有一句说给人听的原句作依据，具体地方仍只取引用的原句里的词，外放、歌词、口述、对 AI 说的话都不算依据。这会把你看病、去宗教场所、去警局法院这类行踪写进摘要，只在你自己愿意时打开。
  - **怎么关**：去掉 `"place_sensitive"`（或设成 `false`）后重启，新推断的地点回到默认的保守规则；已经存下的留在原来的摘要里。
  - **怎么删放开后存的地点**：例如 `sqlite3 live.db "UPDATE summaries SET body = json_remove(body, '$.place') WHERE json_extract(body, '$.place.prompt_version') = 3"`，只删开着 `place_sensitive` 推断的地点；之后再跑一次[补地点](../reference/data.md)，这些摘要按当时的规则重新推断。
- **怎么关**：去掉租户的 `"place"`（或设成 `false`）后重启，新摘要不再推断地点；已有的留在原来的摘要里。重新生成某段摘要时，新摘要不带旧地点；拆分对话、晚到的录音并进对话时，旧地点当即去掉，之后重写失败、保留旧摘要时也不会再显示。
- **怎么删**：去掉 `"place"` 后，删掉所有摘要里的这个字段，例如 `sqlite3 live.db "UPDATE summaries SET body = json_remove(body, '$.place') WHERE json_extract(body, '$.place') IS NOT NULL"`。

## 为什么保留原始录音

有的同类产品转写完就删掉音频。AllDayRec 反过来：每句话都能点开回放核对，转写错了有底稿可对；以后有了更好的模型，还能把过去重新转写一遍。代价是磁盘空间，以及这些录音需要你自己保管好。

## 录到别人

全天录音一定会录到别人。请告知对方，需要时取得同意，遵守当地法律；有些地方要求所有参与方都同意。

用 MCP 把数据交给 AI 助手时，转写里别人说的话也会发给助手的厂商。录音里的话也可能被当成指令：在用这个连接的会话里，不要给联网和 Shell 工具开自动批准。
