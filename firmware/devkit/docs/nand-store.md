# 裸 SPI NAND 环形存储（W25N01GV / W25N02KV）

板上焊一颗 SPI NAND 代替 TF 卡：录音照旧写成「记录流」（`lr_store.h`），存储层换成自己管理的环形日志。编译期用 `CONFIG_LR_NAND` 切换，TF 版不受影响。U 盘模式（CTRL 0x06）只在 NAND 版去掉。

## 1. 芯片

| | W25N01GV | W25N02KV |
|---|---|---|
| JEDEC ID | EF AA 21 | EF AA 22 |
| 容量 | 1024 块 × 64 页 × 2048 B = 128 MiB | 2048 块 × 64 页 × 2048 B = 256 MiB |
| 备用区 | 64 B / 页 | 128 B / 页 |
| 片上 ECC | 1 bit / 528 B | 8 bit |
| 出厂坏块上限 | 20 | 40 |
| 擦写寿命 | 10 万次 | 6 万次 |
| 深度掉电 DPD | 无 | B9h / ABh，1 µA，唤醒 1.5 ms |
| BBM LUT（A1h） | 20 条 | 无 |

两颗都是 WSON-8 8×6，引脚兼容。固件读 JEDEC ID 自动认出是哪一颗，块数、ECC 状态位的含义和 DPD 跟着芯片走。同一份固件两颗都能用。

接口：SPIM3（nRF52840 唯一的高速 SPI 主机，最高 32 MHz），SPI 模式 0，单线，固件默认 16 MHz。不用 QSPI 外设：
- 它按 NOR 闪存的时序工作，24 位地址加固定的 dummy 周期，和 NAND「先 13h 读页进缓存，再按 16 位列地址读缓存」的两步时序对不上；
- 自定义指令模式一次最多传 8 字节。

引脚和接法见 §11。

## 2. 页的格式

一页只装一个文件的数据。主区 2048 B 放记录流的字节，不足一页时剩下的填 FFh。文件就是现在的 `boot << 16 | segment`。

页头 16 B 放在备用区里**两颗芯片都有 ECC 保护的位置**：每个 16 B 小节的第 4–7 字节（W25N01GV 的 User Data I；W25N02KV 的 UD1 开头 4 字节）。

| 位置 | 字段 | 说明 |
|---|---|---|
| 0x804 | `seq` u32 | 全局页序号，每写一页加 1，不回绕（每秒 2 页可以用 68 年） |
| 0x814 | `file` u32 | 这一页属于哪个文件 |
| 0x824 | `off` u32 | 这一页第一个字节在文件里的偏移 |
| 0x834 | `len` u16、`crc` u16 | 有效字节数（1–2048）；CRC-16/CCITT，算 12 字节页头 + `len` 和主区前 `len` 字节 |

- 0x800（第一个备用字节）永远不写，留给坏块标记。
- 时间戳不放：设备没有时钟，时间来自流里的 'T' 记录。页的先后靠 `seq`。

**写入方式**：02h 一次装入「主区 + 备用区前 56 B」，再 10h 编程，等 BUSY 清零，检查 P-FAIL。整页一次编程，不做部分编程（NoP）：W25N02KV 开着 ECC 时，扇区和它对应的 UD1 必须同一次编程。

**每秒约写一页**：存储层在内存里攒满 2048 B 才编程，`fs_sync` 不触发编程（不然每批 4 KB 会多出一页零头，浪费 1/3）。文件关闭时（换段、关机、升级、低电关机）把零头页写下去。代价是：突然断电或看门狗复位，最多丢内存里这不到一页（约 1 s）。TF 版本来也会丢没写出去的那一批（约 1 s）。

## 3. 环形布局

- 块按物理顺序 0, 1, …, N−1 写，到头回到 0，跳过坏块。块内的页从 0 到 63 顺序写（规格书要求）。
- 内存里两张表：每块第 0 页的 `seq`（`seq0[]`，W25N02KV 占 8 KB），和坏块位图。`seq` 落在哪块：找 `seq0 ≤ seq` 的最新一块，页号 = `seq − seq0`。一块没写满（中途开机、编程失败）也成立，因为下一块的 `seq0` 就接在它后面。
- 写指针 = 最新那块的最后一页之后。要进下一块时**当场擦除**，擦的就是环上最旧的那块（tBE 典型 2 ms）。

## 4. 开机恢复

1. 复位（FFh），读 JEDEC ID，写 SR-1 = 0（上电默认整片写保护），SR-2 设 ECC-E = 1、BUF = 1（W25N01GV 的 IT 版默认 BUF = 0）。
**原则：开机恢复宁可少用一块空间，也绝不擦掉可能有数据的块。** 读错、CRC 错、判断不了的块，一律跳过并保留，这次开机不用、不擦，下次开机再看。开机唯一会擦的块是「下一个要写的块」（最新块之后的那块，也就是最旧的块），擦之前一定先确认它确实比最新块旧，或者里面没有完整的页。

所有读操作出错（SPI 返回错误，或 ECC 纠不了）都会重读，最多 3 次。偶发的 SPI 错误就这样过去了，芯片里真有的错误重读也还在。

页头（0x800–0x837，含坏块标记那个字节）每次都连读两遍，两遍一致才算数；不一致就再读一对，3 对都不一致按「读不出来」处理。比较的是读出来的字节，ECC 状态只看「纠不了」这一档：0（正常）和 1（已纠正）算一样，因为页里有一位处在临界状态时，这一次读要纠、下一次不用纠，纠完的数据是一样的，用旧的 NAND 上很常见。两遍都是「纠不了」时取第一遍，不比字节（纠不了的页每次错的位可能不一样），交给后面按 CRC 和 `seq` 核对。SPI 线上读错一位 ECC 管不了，16 MHz 时余量只有约 2 ns。页头读错不只影响擦哪块：文件表和「已上传指针」（§6，存在 NVS 里）都由这次读数决定，读错的话，手机删了短列的文件以后，没列出来的那段就再也不会上传。多读一遍每块多 0.15 ms，整片约 0.15–0.3 s。

2. **扫块头**：每块读第 0 页的 0x800–0x837，约 0.15 ms 一块，W25N01GV 共约 0.15 s，W25N02KV 约 0.3 s。
   - 读不出来（重读 3 次都失败）→ 保留：这次开机不用、不擦。
   - 0x800 ≠ FFh → 坏块（出厂标记，或我们标的）。如果它的页头像我们的，并且 `seq` 在 seq 上限以下、不比算出来的写指针旧，那它可能是最新块、只是坏块标记那一位坏了（W25N01GV 的 0x800 不在 ECC 范围内），按保留块处理（第 3 步最后一条）。我们自己标坏的块，`seq` 只会比最新块旧；出厂坏块里的乱码几乎不可能正好落在这个范围里。
   - 页头字段合理 → 记下 `seq0`。这里只看页头，还没验 CRC，下面第 3 步再验。
   - 页头不像我们的、或 ECC 纠不了 → 按页整页读：第 0、1、2 页里第一个 CRC 对的页给出 `seq0`（它的 `seq` 减页号）；第 0 页是唯一写过的页、又对不上 → 断电时第 0 页写到一半，没有完整的页，当空块；其他情况 → 保留。
     - 第 0 页 ECC 纠不了、第 1 页是空的，也当空块，没有改成保留。在芯片上，断电时写到一半的页读出来就是 ECC 纠不了，和一页写好以后才坏掉的页分不出来。这种块就在最新块后面，正是断电时正要写的那块。改成保留的话，每次正好断在一块第 0 页上，就多一个永远不擦的块，「已上传指针」也会永远停住（第 3 步最后一条）。当空块最多丢这一页，而这一页的编程本来就没报完成。模拟器里撕页也报 ECC 纠不了，断电测试检查过撕页从来不会导致保留块。
   - 备用区全 FFh、主区第一个字节也是 FFh → 空块。
   - 备用区全 FFh、主区第一个字节不是 FFh（叫它「odd 块」）：可能是断电时第 0 页写到一半（我们写的页 0x800 永远是 FFh），也可能是出厂坏块。W25N02KV 规格书 12.2 节说出厂坏块在主区前两个字节和备用区第一个字节都有标记，但出厂检测流程图写的是「任一处不是 FFh」，所以这里两种情况都按坏块防。
     - 芯片上还没有我们的数据（第一次挂载）：odd 块全是出厂的，在 0x800 写 00h，永久标坏。
     - 以后：只有紧跟在最新块后面的那块可能是我们写到一半的，要擦了再用；其他 odd 块这次开机当坏块。

   要不要二分查块：`seq0[]` 这张表反正要建，读页时要用它来定位，坏块也要在这一步认出来，所以每块都得读一次，二分省不了时间。
3. **找最新块并核对**：`seq0` 最大的块（相同时取环上靠后的那块，见 §5 P-FAIL）当候选。
   - 候选块按页整页读、验 CRC，重新得出 `seq0`。和扫描时读到的不一样（扫描时一位读错）→ 改正，重新选；没有完整的页 → 不是最新块，重新选；判断不了 → 保留，重新选。
   - **块内二分**：在最新的块里二分「页头是不是全 FFh」，找到最后写过的页。只有这一页可能是写到一半断的电（可能页头完整、数据只写了一半），所以要读出整页校验 CRC，不对就退回前一页，这个 `seq` 下次接着用。如果退回到第 0 页之前，这一块不是最新块，重新选。二分途中读失败 → 整块保留，重新选。
   - **核对要擦的块**：最新块之后的那个好块（下一步要擦它）也整页读、验 CRC。它比最新块还新（最新块的 `seq0` 扫描时读小了）→ 重新选；判断不了 → 保留，换再下一块，同样核对。
   - **核对环上的顺序**：从要擦的块开始绕环一圈，有数据的块 `seq0` 应该一路上升。不比前一块大（相等也算：写满的块之间正好差 64，读错一位很容易正好等于前一块）、或比最新块还大的块，整页读一次核对。顺序上看着没问题的错值，靠上面的两遍读拦住。
   - **有块被保留时**：
     - `next_seq` 跳到 **seq 上限**。上限存在 NVS 里（键 `lr/nand_top`），所有写过的 `seq` 都比它小：写指针一到上限，先把上限推到写指针 + 4096 页（8 MB）存进 NVS，再写这一页。按 4 KB/s 算约 35 分钟写一次 NVS。这样不管哪一块、连着几次开机读不出来，以后写的 `seq` 都不会和它里面的重复。
       NVS 里的上限写失败时，内存里的上限不动，下一页再写一次。NVS 被清空（比如用 SWD 整片擦除后重烧，NAND 上的数据还在）时上限是 0，这时退回「保留块数 × 64」的跳号：保留块紧接在最新块后面时，这样就够了。
     - 这次开机 DELETE 不推进「已上传指针」（§6）：保留块里的文件没列出来，也就没上传。下次开机读得出来时，从原来的位置重新列出。代价是这次开机删掉的文件下次会再列出来，App 再传一次，服务器去重，和不按顺序删的情况一样。
     - 第 5 步建文件表时有页头读不出来（两遍读一直对不上，或者读失败），也一样不推进 `up`：这一页可能是某个文件的第一页，这个文件这次没列出来。
   - **擦到一半断电的块**：擦除被打断后，那块的页读出来大多是「ECC 纠不了」，和「有数据的块里页坏了」分不出来，按上面的规则会被永远保留，`up` 也永远停住。所以每次擦块之前，先在 NVS 里记下「准备擦第 N 块」（键 `lr/nand_erase`），擦完不用清，下一次擦别的块时就改掉了。开机时，要擦的那块（最新块后面那块）如果页都对不上，而且正是 NVS 里记着的块，就按空块处理，直接擦掉：它里面的文件在开始擦之前就已经从文件表里去掉、计过丢失了。NVS 里记着的块如果不是要擦的那块，照样保留。擦到一半、但页头还完整、CRC 还对的块，按原来的规则当最旧的块擦掉。
     - 每擦一块（每录 128 KB）写一次 NVS，一天几千次。每次 12 B，16 KB 的 settings 分区有 4 个 4 KB 扇区，每个扇区一天擦一到两次，按 1 万次寿命算能用十年以上。
4. **开机先换新块**：最新块剩下的页不再写，下一页写在下一个好块里，先擦它（第 3 步已经核对过）。这样写到一半的页永远不会被二次编程，断电擦到一半的块也会在这一步重新擦一遍。每次开机最多浪费 63 页（126 KB）。
5. **重建文件表**（在第 4 步擦块之前建，这样被擦掉的没上传文件会计入 `NL_LOST`）：从「已上传指针」（§6）和最旧块里取较新的那个作为起点，一直到写指针，按块走：
   - 每块读首页和末页的页头。同一个文件的页在环上是连续的，所以首末两页是同一个文件，整块就是这一个文件。
   - 首末不是同一个文件，就在块内二分找文件的分界。
   - 一个文件的大小 = 它最后一页的 `off + len`。

   文件表最多 256 项，每项记文件号、首页 `seq`、大小，约 3 KB。最旧的那个文件如果首页 `off ≠ 0`（开头已经被覆盖），整个丢掉，不列出来：App 会从偏移 0 去 READ，在 TF 上一个文件总是从头开始的。
6. 断电写到一半的页在第 3 步认出来（CRC 不对）；断电擦到一半的块在第 4 步重擦。

开机共约 0.2–0.4 s 的 NAND 读，在看门狗允许的 30 s 里很宽裕。

## 5. 坏块、ECC

- **出厂坏块**：开机扫块头时跳过（§4.2）。
- **运行中擦除失败**（E-FAIL）：在 0x800 写 00h 标坏，跳到下一个好块。
- **运行中编程失败**（P-FAIL）：这一页作废，同一个 `seq` 改写到下一块的第 0 页（先擦）。P-FAIL 往往只是少数几位没编程成功，开着 ECC 读回来可能完全正确，所以不能靠「读不出来」来区分。
  - 失败的是第 0 页：这一块没有别的数据，立刻标坏。标坏没写上的话，重启后两块的 `seq0` 相同，按环的顺序取后面那块（它才是改写的那页），失败的那块不占任何 `seq`。
  - 失败的是后面的页：这一块前面写好的页还要用，记为「下次轮到时标坏」，等环转回来要擦它时再标坏、跳过。这个记号只在内存里，重启丢了也没关系：下次再失败会再标一次。
- **标坏的写法**：0x800 写 00h，写的时候临时关掉 ECC（Linux spinand 也是不带 ECC 写坏块标记）。这一页可能已经编程过，开着 ECC 再编程一次会把校验位写在旧的上面。
- **SPI 传输出错**和芯片的 P-FAIL / E-FAIL 分开：驱动把 SPI 错误报成 `-ECOMM`，只有状态寄存器里的 P-FAIL / E-FAIL 才是 `-EIO`，才会标坏块。
- **BBM LUT 不用**。LUT 是给需要连续逻辑地址的 FTL 用的：坏块 A 映射到预留的好块 B。环形日志本来就跳坏块，没有逻辑地址要保持，也就不需要预留块。W25N02KV 也没有 LUT。开机不读也不写 LUT。
- **ECC 状态**（每次 13h 读页之后读 SR-3）：
  - 00：正常。
  - 01：已纠正，照用，计数。
  - W25N02KV 的 11：已纠正，但超过了翻转阈值。照用，计数。
  - 10：纠不了。数据照原样发出去（大部分字节是对的），计数一次。这一块不标坏：数据没法挪走，环转回来时照常擦掉重用；真坏了，那时的擦除或编程会失败，再标坏。
  - 开机扫描时页头纠不了：按页整页读，从后面的页定出这一块的 `seq0`（§4.2），内容照常进索引。
  - 计数进事件日志的 `SD_ERRORS`：CRC 位 = 纠不了，BUSY 位 = 已纠正，OTHER 位 = 编程或擦除失败，TIMEOUT 位 = BUSY 超时。`lr_sync.py` 不用改。

## 6. 已上传、回绕、擦除策略

- App 照旧在文件上传完以后发 DELETE。NAND 版的 DELETE 只是在文件表里把这个文件去掉，数据留在原地，等环转回来时擦掉。
- **已上传指针 `up`**：比它小的 `seq` 都已上传。它等于最旧那个没删的文件的首页 `seq`（没有就等于写指针），存在 nRF 片内的 NVS 里（`settings`，键 `lr/nand_up`）。只有 DELETE 让它往前走的时候才写，相当于一段补传完成时写一次，一天几十次。
  - 不按顺序删的情况：删了 B，但比 B 早的 A 还在。B 只在内存里删掉，重启后会重新列出来，App 再传一次，服务器去重。
  - 「最旧的没删的文件」按 `seq` 取最小的，不按文件表的顺序：一个被保留过的块后来又读得出来，它在环上的位置可能夹在新块中间，它的文件也就列在新文件中间（§4.3）。
  - 开机时有块被保留，或者建文件表时有页头读不出来：这次开机 `up` 不动，也不写 NVS（§4.3）。
  - 已知限制：一块永远读不出来（好几页 ECC 都纠不了）的话，每次开机都保留它，`up` 就一直停住，它后面的文件每次重启都会再列出来、再传一次。擦到一半断电的块不在此列（§4.3）。现场真遇到了，再把这种块记进 NVS。
- **擦除策略**：环上要擦的永远是最旧的块。
  - 最旧的块已经全部上传（`seq` 都小于 `up`）：直接擦。环是按时间顺序写的，最旧的总是最先上传的，「已上传的块优先擦」自然成立。
  - 没上传就写满了：照样覆盖最旧的块（不停止录音），首页在这块里的文件整个从文件表里去掉，事件日志记一条。最旧的文件开头一旦被覆盖，就整个丢掉（§4.5），所以 NAND 版把单个文件的上限 `SEG_MAX` 从 16 MB 降到 4 MB（约 15–30 分钟），这样覆盖时多丢的最多 4 MB。
  - TF 版写满是停止录音（`-ENOSPC`），NAND 版不停。
- **寿命**：128 MiB 的环，按 2.1 KB/s 约 17.7 h 转一圈，一年约 490 次擦写。W25N01GV 10 万次可以用 200 年；W25N02KV 6 万次，环大一倍，也远超所需。

## 7. 映射到 LIST / READ / DELETE

存储层注册成一个 Zephyr 文件系统，挂在 `/SD:` 上，路径和 TF 版一样：`/SD:/LR/BBBBSSSS.BIN`。`lr_store.c` 读写文件的代码一行不改，BLE 协议和 App 都不用改。

| `lr_store.c` 的调用 | NAND 版的行为 |
|---|---|
| `fs_open(…BIN, CREATE\|APPEND)` + `fs_write` | 追加到这个文件。只能是最新的那个文件，或者一个新文件，这样保证同一个文件的页在环上连续 |
| `fs_sync` | 不编程（§2） |
| `fs_close`、卸载 | 零头页写下去 |
| `fs_opendir` / `readdir("/SD:/LR")` | 文件表，从旧到新。大小包括内存里没写下去的零头 |
| `fs_open(READ)` + `fs_seek` + `fs_read` | 在文件的页范围里按 `off` 二分，找到起始页，然后顺序往后读。零头从内存里读 |
| `fs_unlink` | 从文件表里去掉，推进 `up`（§6） |
| `fs_statvfs` | 总量 = 好块容量；剩余 = 总量 − 未删文件的大小 |
| `/SD:/LR/BOOT` | 只读：返回文件表里最新的 boot 号。写入接受但不落盘。boot 号的唯一性照旧靠片内计数 + 4096（`next_boot`） |
| `.metadata_never_index`、`.fseventsd`、`mkdir` | 什么都不做（那是给 U 盘模式下的 macOS 用的） |

`sdcard.h` 那套接口由 `nand_card.c` 实现：
- `mount_sd_card*`：第一次挂载时先放开四根线、LDO 断电 300 ms 再上电（SPI 驱动初始化时 CS 已经拉高，LDO 关着时会经保护二极管反灌，`sdcard.c` 开机也这么做），之后一直开着；复位芯片、读 ID、解除写保护（SR-1 = 0）、开 ECC 和缓冲读（SR-2 的 ECC-E、BUF），恢复，挂载。
- `mount_sd_card_reset`（芯片不回话时）：卸载，四根线放开，LDO 关 300 ms 再开，线恢复成 SPI 驱动设的样子，重新挂载。做法和 `sdcard.c` 救 TF 卡一样。
- `sd_power_off`：卸载并关 LDO（只有调试命令和上面的复位会走到）。W25N02KV 在每次读、同步、关闭之后自己进 DPD，下次操作前唤醒。
- `format_sd_card`：返回 `-EEXIST`。
- `lr_sd_sectors` = 容量 / 512，TIME 里的 `card_kb` 照样有值。
- 事件日志：挂载时 `CARD_ID`（x = 0xEF，a = 0xEFAA21 / 0xEFAA22，b = 恢复用了多少 ms）和 `CARD_SIZE`（x = 2 表示 NAND，a = 扇区数，b = 文件数）；没上传就被覆盖的文件记 `CARD_FULL`（x = 2，a = 个数）。`lr_sync.py` 会解这三种。
- 刚滚动结束、零头已写下去的段，手机马上 DELETE 也可以；只有零头还在内存里的那个文件返回 `-EBUSY`。DELETE 之前先把队列里的批次写下去（`card_drain`），删掉的文件不再接受追加（返回 `-EROFS`），不会以同一个名字、错位的内容再出现。

另外几处小改动：
- `lend()`（U 盘模式）返回 `-ENOTSUP`；`usb.c` 里的 MSC 盘编译时去掉，CDC 串口和 1200 bps 复位保留。
- `append()` 里「剩余空间不足就停止录音」那一段跳过。
- 手机模式（`CONFIG_LR_STORE_PHONE`）NAND 版不开：手机模式是为了让 TF 卡断电省电（卡写一次要醒 1.9 s，多耗 21 mA）。NAND 写一页只要约 2.5 ms，没有这个问题。

## 8. 编译开关

- `CONFIG_LR_NAND`（Kconfig）：开了就编 `nand_log.c`（环形日志，纯 C）和 `nand_card.c`（SPI 命令、文件系统、`sdcard.h`），代替 `sdcard.c`、`sdhc_spi.c` 和 FatFs；`OMI_ENABLE_OFFLINE_STORAGE` 保留（它控制整个存储层），它对 FatFs、磁盘访问的 select 在 NAND 版不生效。`CONFIG_LR_NAND_SPI_HZ` 默认 16000000。

- 板子：`overlay/lr_nand.overlay` 删掉 `sdhc0` 和 `spi2`，NAND 挂在 `spi3` 上（引脚高驱动，§11），片选用 `cs-gpios`，暂用 SD 卡那组引脚。

## 9. 功耗（规格书值，VCC 3.0 V）

| 项 | W25N01GV | W25N02KV |
|---|---|---|
| 待机 ICC1 | 10 典型 / 50 最大 µA | 10 / 50 µA；DPD 1 µA |
| 读 / 编程 / 擦除 | 25 / 35 mA | 25 / 35 mA |
| tRD（开 ECC） | 最大 60 µs | 最大 60 µs |
| tPP | 250 典型 / 700 最大 µs | 250 / 700 µs |
| tBE | 2 / 10 ms | 2 / 10 ms |

一直在录音（2.1 KB/s，每秒约 1.05 页）时的平均电流，按 SPI 时钟分：

| SPI 时钟 | 每页传输 | W25N01GV 典型 / 最坏 | W25N02KV 空闲进 DPD 典型 / 最坏 |
|---|---|---|---|
| 8 MHz | 2.1 ms | 0.073 / **0.159 mA** | 0.064 / 0.110 mA |
| 16 MHz（默认） | 1.05 ms | 0.045 / 0.120 mA | 0.036 / 0.071 mA |
| 32 MHz | 0.53 ms | 0.031 / 0.101 mA | 0.022 / 0.052 mA |

- 算法：每页「传输 2107 B + tPP」，每 64 页一次 tBE。典型按 25 mA、tPP 0.25 ms、tBE 2 ms、待机 10 µA；最坏按 35 mA、tPP 0.7 ms、tBE 10 ms、待机 50 µA。DPD 按 1 µA。
- 记账值按 8 MHz 的最坏 0.159 mA。
- 和早先的粗估（典型 0.07 mA、最坏 0.12 mA）对比：典型值对得上；最坏值偏低，因为规格书最坏待机是 50 µA，单这一项就占 0.05 mA。
- 4.2 KB/s（32 kbps 的上限）时，活动部分翻倍。
- 传输时间按芯片全程 25 mA 算，偏保守：装缓存时实际电流应该更低，规格书没给这一项。
- **加上 LDO**：SGM2036 的静态电流典型 20 µA、最大 26 µA（SGM2036 规格书：空载、VEN = VIN、25 °C），一直开着。R25 的 100 kΩ 下拉再加 30 µA，改成 1 MΩ 后是 3 µA。
  - NAND 存储合计（W25N01GV、16 MHz、R25 = 100 kΩ）：典型 0.045 + 0.020 + 0.030 = **0.095 mA**；最坏按 8 MHz 记账，0.159 + 0.026 + 0.030 = **0.215 mA**。
  - R25 改成 1 MΩ 以后：典型 0.068 mA，最坏 0.188 mA。
- 对照：TF 卡的卡模式整机实测 27.3 mA。

## 10. 测试

`test/nand_check.c` 在电脑上跑，用纯 C 模拟 NAND：一个内存数组，编程只能把位从 1 写成 0，块必须先擦后写，页必须按顺序写，可以注入坏块、P-FAIL、E-FAIL 和 ECC 错误。测的项目：
- 写入、读回、LIST；
- 回绕和覆盖；
- 已上传的块先擦；
- 任意一次编程中途断电（这一页只写进去一部分）以后重启：不丢已经写完的页，序号不重复；
- 擦除中途断电；
- 出厂坏块和运行中坏块；
- ECC 纠正和纠不了；
- 开机二分恢复的结果和全量扫描一致；
- 文件表重建；
- 芯片卡死（编程、擦除超时）：不把块当坏块，之前的数据都在；
- 刚关闭的段马上删除；删除后迟到的追加被拒绝；
- 第 0 页 P-FAIL 但数据其实写对了（标坏写上和没写上两种），环转过去之前和之后；
- 开机时一位读错，整个挂载期间都错（旧块的 `seq` 读大、最新块的 `seq` 读小）；开机时读失败（一次、两次、整个挂载期间）：都不擦块，下次开机数据完整；
- 开机时页头读错一位，只错一次（两遍读拦住）或整个挂载期间都错：中间块的 `seq` 读大但顺序正常、读成和前一块相等、读得比前一块小，以及最新块的坏块标记读错。这次开机文件表完整，手机删掉文件 1 以后再开机，什么都不丢。最新块的坏块标记一直读错时，它的 `seq` 不会被重新用掉，`up` 也不动；
- 要擦的块头两页都写过、CRC 都不对：保留，不擦；接着核对再下一块（它的第 0 页 `seq` 读错，其实是最新块）：也不擦；
- 连续两次开机各保留一块：`seq` 不重复（seq 上限）；最新块被保留时文件 1 只列出一部分，手机删了它，下次开机整个重新列出；被保留的块转过一圈后又读得出来、文件夹在新文件中间：删掉排在最前面的文件，`up` 不会越过它；
- 出厂坏块（只标主区）正好在最新块后面：永不擦除、永不使用；
- 断电撕页有两种：整页都只写了一部分；页头完整、数据只写了一半（隔一个断电点换一种）。

模拟器的 P-FAIL 可以设成「报失败但数据写对了」，读可以注入失败和位翻转，编程按 NoP 4 计数（坏块标记也算）。

- 页头两遍读出来不一样：ECC 状态 0、1 交替（在文件 2 的首页，或文件 1 的末页）；ECC 纠不了、每次错的位不一样；整个挂载期间都读失败。文件表完整，或者 `up` 不动，删掉文件 1 后 `up` 都不会越过文件 2；
- 擦除被断电打断（每页都擦到一半，ECC 纠不了），分两种：环转动途中，和开机时的那次擦除。下次开机重擦，不保留，`up` 照常前进。NVS 里记着、但不是要擦的那块，保留；
- seq 上限：NVS 写失败，下一页重写；NVS 被清空，保留块照样跳过；正好等于上限的那一页、和比上限小 1 的那一页，都不会被重新写；出厂坏块里读成页头、`seq` 在上限以上的乱码，不当保留块。

模拟器里断电撕掉的页读出来报 ECC 纠不了（和芯片一样）；擦到一半断电时，每页可能擦掉、原样保留，或者擦到一半（ECC 纠不了）。断电测试还检查重启后没有保留块，`up` 也没被停住。

变异测试：把 `nand_log.c` 改一处再跑 nand_check，下面 28 种改法都会被抓到（脚本不进仓库）。
- 去掉保留块的 seq 跳号；

## 11. PINS（给画板）

**电源**
- 保留原来给 TF 用的 SGM2036-3.0 LDO（U3），由 VSYS 供电，输出 3.0 V 给 NAND。C54、C55、R25 都留着，NAND 旁边再放一颗 0.1 µF 去耦。
- 不能接 VDD：REG0 对外最多给 25 mA，NAND 峰值 35 mA。
- EN 仍接 P0.31（`sd-pwr-gpios`）。固件开机拉高，之后一直开着；NAND 卡死（BUSY 超时）时断电再上电救它（`mount_sd_card_reset`）；System OFF 前关掉。
- **R25 要改大**：EN 被拉高时，100 kΩ 下拉一直在耗 3.0 V / 100 kΩ = 30 µA，比 LDO 自己的静态电流还多。SGM2036 的 EN 自带约 7 MΩ 内部下拉，外接电阻只管首次烧录前 GPIO 悬空的那段时间，建议改成 1 MΩ（3 µA）。
- 电源分档：W25N02KV 空闲时进深度掉电（B9h，1 µA），写之前唤醒（ABh，等 1.5 ms）；W25N01GV 没有深度掉电（指令表里没有 B9h），空闲时就是待机，10 典型 / 50 最大 µA。
- `/WP`（引脚 3）、`/HOLD`（引脚 7）各用 10 kΩ 上拉到 NAND 的 3.0 V。单线 SPI 用不到它们，但悬空会误触发写保护或暂停。

**信号**：/CS（引脚 1）、DO（引脚 2，接 MISO）、DI（引脚 5，接 MOSI）、CLK（引脚 6），GND 是引脚 4。

**SPIM3 跑 16 或 32 MHz 的要求**（nRF52840 PS v1.5）
1. **不能用标着 low frequency I/O 的引脚**（引脚表 7.1，在射频附近）：P0.02、P0.03、P0.09、P0.10、P0.28–P0.31、P1.01–P1.07、P1.10–P1.15。
   - N4 现在 SD 用的 CS P0.20、MOSI P0.22、SCK P0.24、MISO P1.00 都不在这张表里，可以照用。
   - 电源使能 P0.31 是低频脚，但它只在开机和救芯片时翻一次，不受这条限制。
2. **高驱动**：PS 6.25.7 的注 32 写着高码率可能需要高驱动。SCK、MOSI、CS 设成 H0H1（overlay 里 `nordic,drive-mode = <NRF_DRIVE_H0H1>`）。高驱动 25 pF 时上升 / 下降沿 5 ns，标准驱动要慢得多。
3. **时序**：nRF 要求 MISO 在采样沿之前 19 ns 建立（tSPIM,SUMI）；NAND 在 CLK 下降沿之后 7 ns 内出数据（tCLQV，W25N01GV 和 W25N02KV 都是 7 ns）。
   - 16 MHz：半个周期 31 ns，减去 7 ns 加沿和走线约 3 ns，剩约 21 ns，刚好满足 19 ns，余量只有约 2 ns。
   - 32 MHz：半周期只有 15.6 ns，要靠 SPIM3 的 RXDELAY 推迟采样（NCS 设备树默认 `rx-delay = <2>`），要在板子上实测确认。
   - 所以固件默认 16 MHz。32 MHz 在板上做读回测试以后再开：开机恢复会校验 CRC，读错会在事件日志里看到。
4. **走线**：四根线尽量短、长度接近（≤ 20 mm），远离天线和晶振，下面是完整地平面。CLK 上可以预留一颗 0 Ω / 22 Ω 串联电阻位，用来调过冲。
5. **勘误**：
   - nRF52840 errata 198：SPIM3 的发送缓冲和别的 EasyDMA（PDM、射频）在同一块 8 KB RAM 时，发出去的数据可能出错。固件打开 `CONFIG_NRF52_ANOMALY_198_WORKAROUND`，由 nrfx 处理。
   - errata 195：SPIM3 关掉以后还在耗电。nrfx 2.7 自带这条 workaround。

- VCC 是 Pro Micro 右排的 VCC 脚：3.3 V，由 P0.13 开关（固件当成 `sd-pwr-gpios`，开机打开，救芯片时断电再上电）。W25N 的 VCC 范围 2.7–3.6 V，3.3 V 可以。
- 线尽量短（10 cm 以内）。杜邦线上先用默认的 16 MHz；读回出错（`SD_ERRORS` 里 CRC 计数涨）就把 `CONFIG_LR_NAND_SPI_HZ` 降到 8000000 再试。
- 固件：`./lr.sh build promicro-nand`（型号 LR-PN）。
- 实测要看的：开机 `CARD_ID` 认出芯片和恢复用时；录一段以后 LIST / READ / DELETE；断电重启后数据还在；有 DM40B 的话量一下录音时的存储电流，和 §9 的估算对比。
